## Design Context

### Users
Terminal-native developers who work with AI coding agents (Claude Code) across multiple machines. They live in tmux, value efficiency over aesthetics, and judge tools by whether they get out of the way. Context: discovering tmux-box for the first time, or returning to access the hosted SPA.

### Brand Personality
**Crisp. Tool-like. Direct.** No marketing fluff, no unnecessary flourish. The interface should feel like a well-made instrument — purposeful, precise, confident. "We built this because we needed it" energy.

### Aesthetic Direction
- **Tone:** Utilitarian developer tool — closer to a man page than a marketing site, but with enough craft to signal quality
- **Dark theme:** Lift the current near-black (#0a0a1a) to a comfortable dark gray. The goal is "editor at night" not "void"
- **Accent:** Purple (#7a6aaa) stays as brand color from the SPA. Adjust lightness for better contrast where needed
- **Typography:** Monospace or semi-monospace for headings to reinforce terminal identity. Clean sans-serif for body
- **Layout:** Generous whitespace, left-aligned where natural, avoid centering everything
- **Anti-references:** No glassmorphism, no gradient text, no glowing borders, no "AI startup" aesthetic. No cards-inside-cards. No identical card grids with rounded icons above every heading.
- **Theme support:** Dark (default) and Light, using existing 21 semantic CSS tokens

### Design Principles
1. **Substance over style** — Every visual element must serve a purpose. If it doesn't help the developer understand what tmux-box does, remove it.
2. **Terminal affinity** — The design should feel native to people who spend their day in a terminal. Monospace touches, command-line references, and code snippets are welcome.
3. **Quiet confidence** — Don't shout. Let the product speak through clear descriptions and real screenshots. Understated > flashy.
4. **Respect the reader** — Dense information is fine. Developers scan fast. Don't pad content for visual balance.
